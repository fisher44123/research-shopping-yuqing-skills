# Shopping Research 四维设计规范与案例沉淀

## 1. 经典排雷案例范式（先认清物理真身，再比价格）

| 常见购买误区 | 循证纠偏原则 |
| :--- | :--- |
| 以为某清洁粉什么污渍都能洗 | 先分清“氧化性污渍”与“油溶性笔迹”，在推荐前先告知物理失效边界 |
| 只看 9.9 元超大斤数白牌 | 低价散装必查执行标准与有效成分下限，警惕有效成分含量极低的伪低价 |
| 盲目囤 25kg 工业/家庭大包装 | 核算囤货受潮失活与保质期损耗，便宜大碗用不完反而更贵 |
| 迷信精装 500g 小瓶性价比 | 用 `sku_check.py --dose` 算清「单次使用成本」与折合每斤价，直接拆穿包装税 |

## 2. 四维执行标准（审美 / 交互 / 逻辑 / 审计）

| 维度 | 核心标准 | 常见反例（禁止出现） |
| :--- | :--- | :--- |
| **审美与可读性** | 区块图标作明确导航；表格严格 ≤4 列且一列只放一类信息；主数字（到手价/单次成本）高亮；状态色标 `🟢🟡🔴❓` 清晰 | 整段纯文字堆砌；规格/价格/差评混塞同一格；用模糊形容词掩盖不确定性 |
| **交互节奏** | 每次停顿均提供极简编号与 `➡️推荐默认项`，确认成本极低；停顿前声明过的矩阵与候选即契约 | 未经确认擅自跳步；停顿发一堆开放性长问句；确认完私自偷换候选型号 |
| **推理逻辑** | 五维需求激活卡先行；A/B 需求先分层；每个价格经 `sku_check.py` 校验，`mismatch` 一律硬拦截，所有主张带 `[SRC-xxx]` 锚定 | 跳过成分机理直接晒商品链接；写“据网友普遍反馈”却无来源编号；把不同代际的型号放一起比最低价 |
| **审计可追溯** | 多批检索区分阶段编号（如 `SRC-L1` / `SRC-L2`）；受阻渠道状态原样保留；正文仅精选 2 条五维一手证据，严禁展示地域属地元数据 | 正文刷屏粘贴数十条原始爬虫日志；隐瞒个别比价站点超时不报 |
