# 通用循证调研工作流（Quick Research · Verifiable Edition）

核心定位：**先定检索边界、再双面取证（正面实锤 + 反向退坑）、最后过机器确定性核验与独立审核。**
本 Skill 与具体数据抓取器完全解耦（**BYOT — Bring Your Own Tools**），可无缝挂载合法的搜索 MCP、官方开放 API 或授权浏览器检索工具。

> **按需参考目录（渐进披露）**：
> - `references/adapter-schema.json`：外部检索适配器向本套件交付证据的标准 JSON 契约
> - `references/review_gate.md`：独立审核闸门规范（G1–G5 硬门禁与人机分工）
> - `references/benchmark-playbook.md`：对标开源项目改进方法论（七步流程与三维验尸模板）

---

## 一、意图分流与前置原则

1. **三路意图严格分流**：
   - 通用技术排错、开源评估、架构对比、事实查证 → **留在本 Skill**；
   - 用户意图是「买哪款 / 值不值 / 比价 / 怎么用才划算」 → **立即中止并让位 `shopping-research`**（已采证据直接移交，不重复检索）；
   - 用户意图是「大家怎么看 / 网上风评 / 翻车了吗 / 水军清理」 → **立即中止并让位 `yuqing-research`**。
2. **⚡ 意图明确直出 vs 🎯 范围过宽澄清**：
   - 主体与问题边界清晰时，打包查询后直接输出结论，并给出 2~3 个可继续深挖的分支；
   - 问题过于宽泛时，最多提出 2~3 个带推荐默认项的选择题，严禁形式主义连续反问。
3. **🎯 检索词主体锚点门禁**：
   - 每条查询必须显式包含被调研主体与意图词（如 `<主体> 避坑 OR 缺陷`），严禁只搜抽象概念。
   - 单次任务控制检索批次数，若连续 2 轮无有效增量信号即触发熔断，切回第一性原理推导并如实报告覆盖空白。

## 二、去伪存真四铁律（Deep Fact-Check & Via Negativa）

1. **一手官方与原始讨论优先**：
   - 优先采信官方文档、GitHub 源码 / Issue / Release Notes、社区原始讨论帖与长测实录；
   - 同一篇通稿被多家站点转载或洗稿时，只计为 **1 个独立信源**，严禁靠转载量凑虚假共识。
   - 必须做好**实体对齐（Entity Alignment）**：严禁将老款、同名不同代、其他版本的性能参数或故障嫁接到目标对象上。
2. **Via Negativa 反向退坑必查**：
   - 任何技术选型、软件库、工具或方法论调研，**必须主动并入反向退坑检索词**：`弃用 OR 换到 OR 避坑 OR 致命缺陷 OR 停更 OR 替代`。
   - 若反例检索返回 0 条，报告中只能严谨表述为**「本次检索范围内未见公开负面反馈」**，严禁写成「零缺点 / 完全完美」。
3. **开源项目三维验尸（Vital Signs）**：
   - 评估开源项目是否值得投入时，必须基于官方仓库实测核查三项生命体征：
     1. **最近真实代码 Commit 日期**（警惕只更新 README 或停更超 12 个月）；
     2. **未关闭 Issue 与 PR 的活跃度及维护者响应速度**；
     3. **是否存在 `archived=true` 归档标记或大版本断代重写（Breaking Changes）**。
4. **工具异常显式透传（Fail-Fast 铁律）**：
   - 若 BYOT 检索器在 `source_health` 中返回 `timeout`、`auth_required`、`rate_limited`、`blocked` 或 `error`，**必须在报告开头逐源如实写明受阻渠道与影响范围**，严禁把采集受阻粉饰为「全网无讨论」。

## 三、BYOT 检索契约与零隐私底线

- 任意搜索 MCP、API 脚本或检索流水线产出的原始证据，均建议按 `references/adapter-schema.json` 规范落盘为注册表 JSON（含 `run_meta`、`source_health[]`、`evidence_items[]`），为每条证据分配唯一可追溯 ID（如 `SRC-001` 或分阶段 `SRC-L1-001`）。
- **零个人隐私采集**：不得收集、留存或展示任何用户的地域属地、设备指纹或敏感凭据字段；外网与中文区信源分开统计，不混算百分比。

## 四、四栏高密度交付结构与确定性核验闭环

所有事实主张必须绑定 `[SRC-xxx]` 并标注 `[年份 | 独立信源数]`（例如 `[2026 | 独立源 5]`）：

1. **🎯 一句话核心结论**：直给可执行判断，若存在受阻信源紧跟 `> ⚠️ 信源健康提示` 说明缺失边界与时效性。
2. **🟢 已实锤共识 / 🔴 踩坑边界与反方拔草**：双栏对照呈现正面证据与真实翻车边界。
3. **🟡 社区争议与 ❓ 孤证盲区**：保留未定论分歧与单源孤证，明确指出哪些结论尚缺一手验证。
4. **📂 证据精选与确定性核验收尾**：
   - 精选 1~2 条代表性一手证据（含精确发布时间、作者/ID、互动量、原始出处链接、核心原话摘录）；
   - 先过作者十项自审（结论被证据严格蕴含、无跨代错配、不把未覆盖写成不存在、数字可回溯等），并输出 `### ✅ 交付前自审`；
   - **运行确定性机器核验**（硬拦不通过禁止直接交付）：

```bash
# 1. 核对正文 SRC 编号是否全部存在于注册表、有无只引编号却文不对题
python tools/citation_audit.py <报告路径.md> --registry <registry.json> --strict

# 2. 核对统计数字是否带来源、声称是否有凭证、是否存在越级用词与缺口说明
python tools/review_check.py <报告路径.md> --strict
```

   - 对重要或高决策成本报告，按照 `references/review_gate.md` 在**独立子上下文/新会话**完成 G1–G5 审核并用 `tools/review_log.py` 留痕。
