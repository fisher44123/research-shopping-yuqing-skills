# 独立审核闸门规范（Adversarial Review Gate v5）

> 适用：`quick-research` / `shopping-research` / `yuqing-research`
> 核心原则：**只要一条规则能被确定性代码判定，就不该交给大模型主观打分；但只有会直接误导读者的硬伤才配当硬拦门禁。**

---

## 0. 双层设计：规则外置 + 轻重分级

早期纯依靠 LLM “第二遍阅读打分”的审核常常流于形式，或者将所有格式检查都设为硬阻塞，导致正常报告因误报被反复打回。成熟的做法是将校验拆为两层：

- **Deterministic eval metrics（确定性检查）**：`tools/review_check.py` + `tools/citation_audit.py` + `tools/sku_check.py` 负责形式、数字溯源、引用真伪与商品实体对齐，同一输入永远同一结果。
- **Model-assisted / Human review（语义核对）**：只在独立上下文或由人工抽查「结论是否真的被原文支持」「反方提问是否切中要害」。

| 改动机制 | 具体实现 |
| :--- | :--- |
| 规则全部外置 | 词表、正则表达式、阈值、硬拦/提示划分全部写入 `tools/review_rules.json`，调松紧只改配置，不改代码 |
| 双级分流 | `fail_on`（硬拦，退出码 `1`）仅保留 **数字没来源**、**声称验证却无凭证** 两项硬伤；越级词、缺口章节、反向质疑条数等降级为 `warn_on` 提示 |
| 上下文独立 | 必须另起新会话或独立子 Agent 审阅「正文 + 证据注册表」，严禁同一推理流里自己给自己盖章“已通过” |

```bash
python tools/review_check.py <报告路径.md>
python tools/review_check.py <报告路径.md> --strict
python tools/review_check.py <报告路径.md> --rules path/to/custom_rules.json
```

## 1. 结论强度边界：为什么需要外部锚点

无外部反馈时，大模型对自身输出做“反思纠错”往往无法稳定提升准确性，且模型作为裁判存在自我偏好与位置偏差。因此本规范将审核锚点强制绑定在外部真实文件（`registry.json` 与原始摘录）之上：**有外部锚点核对时审核有效，无外部锚点纯空对空复读时不可靠**。

---

## 2. 执行机制（可检测分离）

1. **作者自查 ≠ 独立通过**：作者完成交付前的「十项自审」只负责排查显性漏项，无权直接宣告“独立审核通过”。
2. **独立消息执行**：将待审正文与证据注册表交给独立上下文/子 Agent，并在审核结果首行写明可验证凭证：
   ```text
   审核上下文：<subagent-id / new-session-id> ｜ 首次读取正文时间：<YYYY-MM-DD HH:MM:SS>
   ```
3. **拒绝同一上下文自判**：`tools/review_log.py` 会直接拦截 `--context self` 等自审标识，且若 `--context author-*` 尝试写入 `--verdict 通过` 将报错拒绝。

---

## 3. 五条门禁（G1–G5）：机器栏先过，再交语义栏

| # | 门禁 | 机器可判部分（`review_check.py` / 配套工具） | 语义/人工抽核部分 |
| --: | :--- | :--- | :--- |
| G1 | 数字可回溯 | 统计量（带计量单位）附近 180 字或同段落内是否有来源标记；设计参数/版本号自动豁免 | 被标注的 `SRC-xxx` 原文是否**真支持**这个具体数值 |
| G2 | 对象错配 = 0 | 消费品场景由 `sku_check.py` 做字段级硬比对（品牌/型号/后缀/代次/容量/颜色） | 非消费品跨版本、跨架构对比是否存在张冠李戴 |
| G3 | 结论强度匹配证据 | 越级词（如 `全量 / 必然 / 100% / 唯一可靠`）所在段落是否 ≥2 处来源；否定语境自动放行 | 全文语气是否越界（如把单一来源写成行业共识） |
| G4 | 覆盖缺口已写明 | 是否存在「缺口 / 未闭合 / 仍未解决 / 未做」章节；台账内是否无作者自判通过 | 未检索到的边界与降级前提是否诚实交代给决策者 |
| G5 | 反向质疑 ≥3 条 | 条数是否达到配置下限（默认 `min_reverse_questions: 3`） | 提出的最可能翻车场景是否真正切中要害 |

> **执行顺序**：机器栏任一 FAIL，先修改正文直到机器栏全绿，再送独立上下文或人工做语义抽核。

---

## 4. 轮次上限与「带病交付」协议

- 最多重写 **2 轮**，防止无限循环烧光 Token。
- 若第 2 轮重写后仍未通过关键门禁，允许交付但必须在正文**第一行**显式声明缺口：
  ```text
  ⚠️ 未通过独立审核（缺口：G1 数字 X 缺来源凭证 / G4 未覆盖边界 Y）
  ```

## 5. 台账落盘与领域附加核查

独立审核完成后，调用 `tools/review_log.py` 将本次结果追加至台账供人工抽查：

```bash
python tools/review_log.py \
  --context "subagent-review-01" \
  --gates "G1:PASS;G2:N/A;G3:PASS;G4:PASS;G5:PASS" \
  --verdict "通过" \
  --target "reports/target_report.md" \
  --worst "正文第3节对备选方案的长期维护成本缺乏实测样本"
```

*(注：`tools/review_log.py` 目前校验五条门禁格式为 `PASS|FAIL|PARTIAL`，若某门禁不适用请记录为 `PASS` 并在备注或审核文本中标 `N/A`。)*

领域附加核查重点：
- **通用调研 (`quick-research`)**：渠道选择与问题场景是否匹配；受阻信源是否如实透传；绝无任何个人或地域属地字段。
- **购物选购 (`shopping-research`)**：决赛圈每款候选价格必须经过 `sku_check.py` 对齐且标明采集日期；未采到实价的候选保留并标 `unpriced`。
- **舆情研判 (`yuqing-research`)**：中文区与海外样本严格分开计算比例；未启用全量通道时明确注明采样限制。

## 6. 已知不可解边界（坦诚说明）

1. **规则之外的语义挪用**：`review_check.py` 能检查“数字旁有没有写 `SRC-001`”，`citation_audit.py` 能做词项重合度预警，但两者都不能百分百取代人类读一遍原文确认数值没有张冠李戴。
2. **源头污染风险**：若上游证据注册表本身收录了洗稿内容，核验脚本只会基于该注册表核对形式一致性，仍依赖上游 BYOT 源头选育。
